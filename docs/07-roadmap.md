# 07. План разработки (маленькими этапами)

Принцип: **один этап — одна проверяемая ценность**, без «больших прыжков». После каждого этапа
приложение собирается и запускается; изменения читаемы и обозримы.

Легенда статуса: `[ ]` не начат · `[~]` в работе · `[x]` готов.

## Этап 0. Фундамент (документация, скилы, бойлерплейт)

- [x] `docs/` — архитектура, стек, соглашения, план (этот набор).
- [x] Скил(ы) для агента — правила FSD/TS/стиля, зафиксированные в `docs/`.
- [x] Приведение скаффолда в порядок: `go.mod` module-имя, `build/config.yml` (info: company/
      product/identifier), чистка демо (`GreetService`, `time`-event, демо-компоненты).
- [x] Настройка фронтенда: TS strict, точки входа, `shared/api` каркас, токены стилей.

## Этап 1. Каркас приложения

- [x] Layout: sidebar + область контента; переключение экранов без роутера (реестр `app/navigation.ts`).
- [x] Экраны `pages`: downloads / proxies / history / settings (заглушки).
- [x] Светлая/тёмная/системная тема (`shared/lib/theme.ts`, токены, переключатель).
- [x] Первый Go-сервис (`AppService.GetAppInfo`) — сквозная проверка биндингов.

## Этап 2. Настройки и пути

- [x] `paths` + `config`: загрузка/сохранение `config.json`, дефолты, версия схемы.
- [x] `SettingsService`: чтение/запись.
- [x] UI: выбор папки загрузки (нативный диалог Wails), прочие базовые настройки.

## Этап 3. Менеджер зависимостей

Разбит на узкие подшаги (3.1a–3.1g — yt-dlp; 3.2 — deno; 3.3 — ffmpeg).

- [x] **3.1a** `deps`: типы + чистые функции (`assetName`, `parseSums`, `releaseRepo`, `binaryName`) + тесты.
- [x] **3.1b** `deps`: сетевой слой — `github.go` (релиз) + `download.go` (скачивание + SHA-256 + атомарная замена) + офлайн-тесты (`httptest`).
- [x] **3.1c** `deps`: `manifest.go` + `Manager` (`Inspect`/`Install`/`Remove`) + тест полного цикла.
- [x] **3.1d** `DepsService` + регистрация в `app.go` + биндинги + обёртки `shared/api`.
- [x] **3.1e** `entities/dependency`: Pinia-стор (единый источник: список, `refresh`, `checkUpdates`, `install/remove`, `removeManaged`, `hasUpdates`) + селекторы.
- [x] **3.1f** компактный чеклист зависимостей: inline-чипсы в футере главной + действие «Проверить».
- [x] **3.1f+** полная очистка управляемых зависимостей (`Manager.RemoveAll`/`DepsService.RemoveAllManaged`, кнопка «Удалить загруженные»).
- [x] **3.1g** детальный блок (назначение, версии, источник, когда обновлялось, свежая версия, действия) — виджет `deps-detail` на вкладке «Зависимости» в «Настройках».
- [x] События `dep:*` + троттлинг прогресса установки (события `dep:progress`/`dep:state`; прогресс в UI).
- [x] Политика источника зависимости: `auto` / `system` / `managed` (выбор в UI).
- [x] **3.2** `deno` (обнаружение системного → скачивание) + `spec`-реестр зависимостей и распаковка zip. Передача `--js-runtimes` — в Этапе 4 (загрузки).
- [x] **3.3** Ленивая установка `ffmpeg`/`ffprobe` (ffmpeg-static; Windows ARM64 — FFmpeg-Builds); модель deps обобщена на «компоненты» с форматами gzip/zip и проверкой через GitHub `digest`.

> Текущее состояние и промпт для продолжения — в [`08-progress.md`](./08-progress.md).

## Этап 4. Одиночная загрузка

- [x] `ytdlp`: сборка аргументов (чистые функции) — `internal/ytdlp/args.go`; запуск процесса,
      парсинг прогресса (`--newline` + `--progress-template`), отмена — `process.go`/`progress.go`.
- [x] `DownloadService`: создать задачу, отменить, получить список форматов (`-J`) и варианты качества.
- [x] UI: добавление URL, кнопки качества, таблица форматов, прогресс, статус, отмена.
- [x] `task:*` события + стор задач (Pinia).

## Этап 5. Очередь и история

- [x] `download`: очередь, последовательный запуск (`concurrency = 1`), пауза/возобновление (`queued`/`running`/`paused`, `--continue`).
- [x] `history`: запись завершённых задач (`internal/history`), просмотр/очистка в UI (`HistoryService`, экран «История»).

## Этап 6. Пул прокси и автопереключение

- [x] `proxy`: модель пула, импорт списком, персистенция (`internal/proxy`: `Proxy`/`ParseList`/`Store`).
- [x] `proxy`: пул и ротация (`Pool.Pick`, стратегии round-robin/random/least-used/lowest-latency/sticky; failCount + cooldown/backoff), рантайм-состояние (`View`).
- [x] `proxy`: health-check (ленивый TCP/SOCKS5-рукопожатие — `Check`/`CheckAll`).
- [ ] `proxy`: реальная проверка `yt-dlp --simulate --proxy` (по требованию). CRUD из UI.
- [x] Классификация сетевых ошибок (`ytdlp.ClassifyError`) и автопереключение с retry: перезапуск с новым `--proxy` (`download.attempt`, `--continue` включён по умолчанию).
- [x] UI: управление пулом (`ProxyService`: импорт списком, CRUD, статусы, стратегия, «Проверить») — экран «Прокси», `entities/proxy`.

## Этап 7. Пресеты загрузки

- [ ] `download-preset`: именованные наборы настроек (формат, папка, субтитры, метаданные…).
- [ ] UI: создание/редактирование/применение пресетов.

## Этап 8. Полировка

- [ ] Производительность: виртуализация длинных списков, профилирование прогресса.
- [ ] Обработка ошибок и «дружелюбные» сообщения.
- [ ] Локализация интерфейса (минимум ru/en).

## Этап 9. Упаковка и поставка

- [x] Linux: `deb`, `rpm`, `AppImage`, `pkg.tar.zst` (AUR) — `wails3 task linux:package`.
- [x] Windows: установщик NSIS + портативный `.zip` (портативный zip — как основной артефакт).
- [x] macOS: универсальный `dmg` (Intel + Apple Silicon) — `darwin:package:universal` + `create:dmg`.
- [x] Метаданные (имя/идентификатор/версия/копирайт/лицензия) приведены в порядок; версия — 0.1.0.
- [x] CI: сборка и публикация GitHub Release по тегу `v*` (`.github/workflows/release.yml`).
- [x] Убедиться, что **инсталлятор не содержит внешних бинарников** (зависимости ставятся в рантайме).
- [ ] Подпись/нотаризация артефактов (нужны сертификаты; задачи готовы).

## Definition of Done для каждого этапа

- Код типизирован и строго проходит `tsc`/`vue-tsc` и `go build`/`go vet`.
- Нет утечек подписок/горутин/процессов.
- Публичные интерфейсы задокументированы по месту.
- Обновлены `docs/`, если поведение отклонилось от описанного.
- Приложение собирается и запускается на текущей ОС.
