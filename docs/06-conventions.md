# 06. Соглашения кода

Цели: **читабельность, типовая строгость, отсутствие утечек, предсказуемая производительность.**
Код читает человек — поэтому простота важнее «умности».

## Общее

- Язык комментариев/документации — русский; идентификаторы (имена) — английские.
- Комментарий объясняет **зачем**, а не **что**; не дублирует код.
- Одна ответственность на функцию/модуль; маленькие функции.
- Публичные сущности пакета/слайса экспортируются через единую точку (`index.ts`, `Package` doc).

## TypeScript / Vue

### Конфигурация

- `typescript@6.0.3`, конфиг максимально строгий:

```jsonc
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "moduleDetection": "force"
  }
}
```

### Правила

- **`any` запрещён.** Для неизвестного — `unknown` + сужение типов.
- **`import type`** для типов (`verbatimModuleSyntax`).
- Всегда **`<script setup lang="ts">`**; `defineProps`/`defineEmits` — через типы:
  ```ts
  const props = defineProps<{ task: DownloadTask }>()
  const emit = defineEmits<{ (e: 'cancel', id: string): void }>()
  ```
- **Никаких `enum`** (исключение — оправданные случаи); предпочитаем union-типы и `as const`.
- `readonly` для структур, которые не должны мутировать.
- Функции чистые, где возможно; побочные эффекты — на границах (в `features`/`api`).
- Явный тип возврата у экспортируемых функций.

### Vue-специфика

- Computed для производных значений; не храним то, что можно вычислить.
- **Не** используем `watch` для того, что решается `computed`.
- Тяжёлые объекты/списки — `shallowRef` + `markRaw`; избегаем глубокой реактивности.
- **Утечки:** все подписки (события Wails, `addEventListener`, таймеры) отписываются в
  `onScopeDispose`/`onUnmounted`. Правило: «подписался — тут же предусмотрел отписку».
- Никаких обращений к биндингам Go из компонентов — только через `shared/api`.

### Производительность UI

- События прогресса — уже throttled с бэкенда; в UI не выполняем тяжёлые вычисления на каждое
  событие (кэшируем/батчим).
- Длинные списки — виртуализация (`@tanstack/vue-virtual`, при необходимости).
- Ключи `v-for` — стабильные (`id`, не индекс).

## Go

### Стиль

- `gofmt`/`goimports` обязательны; `go vet` — без замечаний.
- Экспортируемое — с doc-комментарием, начинающимся с имени.
- Имена короткие и точные; без венгерской нотации.
- Ошибки: возвращать, а не паниковать; оборачивать `%w`; проверять через `errors.Is/As`.
- `context.Context` — первым аргументом; не хранится в структурах.
- Конкурентность: `errgroup`/`sync.WaitGroup`; никаких «голых» горутин без жизненного цикла.
- Нет глобального изменяемого состояния; зависимости — через конструкторы.
- Каналы — для потоковой передачи; мьютексы — для защиты состояния.

### Тесты

- Чистую логику (сборка аргументов `yt-dlp`, классификация ошибок, ротация прокси,
  парсинг прогресса) — выносим в чистые функции и покрываем табличными тестами.
- Тесты — рядом с кодом (`*_test.go`).

## Взаимодействие Go ↔ TS

- Методы сервисов — `PascalCase`; DTO-структуры сериализуются в `camelCase` JSON.
- Общие DTO: `ID` — `string`; время — ISO-8601 (строка) или epoch-ms (число); выбираем **epoch-ms**
  для рантайма, ISO — для отображения.
- Ошибки сервисов → DTO `{ code: string; message: string }`, где `message` пригоден для показа.
- Имена событий — в одном месте (пакет `events` в Go и `shared/config/events.ts` в TS),
  синхронно.

## Именование

| Сущность | Стиль | Пример |
|----------|-------|--------|
| Go пакет | lowercase, одно слово | `proxy`, `download` |
| Go тип/метод | PascalCase | `ProxyPool`, `AddTask` |
| TS тип/интерфейс | PascalCase | `DownloadTask` |
| TS функция/переменная | camelCase | `formatBytes`, `taskList` |
| Vue-компонент (файл) | PascalCase | `TaskList.vue` |
| FSD-слайс/папка | kebab-case | `manage-proxy-pool` |
| Константы | UPPER_SNAKE | `MAX_RETRIES` |
| Событие | `domain:action` | `task:progress` |
