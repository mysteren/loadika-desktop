## Ключевые решения

### Р1. Wails v3 вместо Electron

- **Решение:** Wails (нативный webview) + бэкенд на Go.
- **Почему:** один лёгкий бинарник (~10–15 МБ), низкое потребление памяти, отличный инструмент
  для управления процессами и конкурентных health-check. Node/TS остаются только как тулчейн фронтенда.
- **Следствие:** вся «серверная» логика — на Go; фронтенд — тонкий Vue-слой.

### Р2. Управление состоянием — Pinia

- **Решение:** Pinia, но **только** для разделяемого между компонентами состояния
  (список задач, пул прокси, настройки).
- **Почему:** маленькая, типобезопасная, идиоматичная для Vue 3; локальное состояние
  компонента — обычные `ref`/`computed`, глобальный стор не используется как свалка.

### Р3. UI — собственные компоненты + `reka-ui`

- **Решение:** базовые компоненты (кнопки, поля, карточки, sidebar, прогресс) пишем сами на
  CSS-токенах; `reka-ui` — только для сложных и a11y-критичных примитивов (dialog, popover,
  tooltip, dropdown-menu, combobox/select, tabs, toast).
- **Почему:** лёгкий и полностью контролируемый десктопный UI без «громоздких» китов.
- **Следствие:** нужен слой дизайн-токенов (CSS-переменные: цвет, отступы, радиусы, тени).

### Р4. Хранение настроек — JSON в каталогах ОС

- **Решение:** `config.json` / `history.json` в каталоге конфигурации ОС, получаемом через stdlib
  (`os.UserConfigDir()`); временные/переустанавливаемые данные — в `os.UserCacheDir()`.
- **Почему:** без сторонних зависимостей, предсказуемо и одинаково на всех ОС.
- **Пути по ОС:**
  - Linux: `~/.config/loadika-desktop/`
  - Windows: `%APPDATA%\loadika-desktop\`
  - macOS: `~/Library/Application Support/loadika-desktop/`

### Р5. TypeScript — strict

- **Решение:** `typescript@6.0.3`, максимально строгий конфиг (`strict` и дополнительные флаги).
- **Почему:** читабельность и типобезопасность; вся кодовая база — типизирована, `any` запрещён.
- Подробности — в `06-conventions.md`.

### Р6. Зависимости управляются приложением

- **Решение:** приложение само обнаруживает/устанавливает/обновляет `yt-dlp`, `ffmpeg`/`ffprobe`,
  `deno`; каждая зависимость — отдельный модуль с единым интерфейсом.
- **Инсталлятор не содержит внешних бинарников** и остаётся минимальным. Стратегия — **system-first**:
  сначала ищем зависимость в системе, иначе скачиваем по требованию (или по кнопке пользователя).
- **Почему:** пользователь не должен ставить что-либо вручную; поведение одинаково на всех ОС;
  маленький дистрибутив и отсутствие GPL-обязательств от перепаковки бинарников.
- Подробности и источники — в `04-dependencies.md`.

### Р8. Темы оформления и логотип

- **Решение:** светлая / тёмная / системная тема **без сторонних библиотек** — через атрибут
  `<html data-theme="light|dark">` и `matchMedia("(prefers-color-scheme: dark)")`.
  Состояние — в `shared/lib/theme.ts`; выбор пользователя хранится в `localStorage`
  (позже переедет в настройки Go). Тема применяется до монтирования приложения (без «вспышки»).
- **Основной цвет (primary):** приглушённый розово-пурпурный (`--color-accent`), не «кислотный»;
  в тёмной теме — более светлый оттенок с тёмным контрастным текстом.
- **Логотип:** `frontend/public/logo.svg` — монохромный силуэт (причёска с вырезом лица) в
  акцентном цвете и с прозрачным фоном; рисуется CSS-маской в сайдбаре и как favicon. Из него
  собирается иконка приложения (см. `08-progress.md` → «Иконки / инструменты»).
